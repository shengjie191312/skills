# 产品原型 Demo 向导

结论：先配置确认，再生成原型。不要在信息不足时直接做最终 HTML，除非用户明确要求跳过确认。

## 快速生成配置器

优先使用脚本，不要手工改大段 HTML 模板。

```powershell
& "C:\Users\乔治\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe" `
  "C:\Users\乔治\.codex\skills\prototype-demo-wizard\scripts\generate_configurator.py" `
  --topic "主题" `
  --prompt "用户原始需求" `
  --output "C:\Users\乔治\Desktop\AI test\prototype-configurator-xxx.html"
```

脚本会自动套用 `templates/configurator-template.html`，并按关键词预设：

- B 端 SaaS、B 端工作台、数据看板、AI 工作台、C 端 App/小程序、C 端内容/社区、官网/活动页。
- 面向对象、色调方向、布局策略、体验重点、业务字段、状态覆盖和修改要求。

生成后只需简短回复文件路径，并提示用户打开 HTML 点选后复制确认单。

## 确认单处理

用户发回“原型生成确认单”后：

- 如果用户未说“确认生成”，先用 4 行复核：页面范围、核心流程、风格、关键交互，并请用户回复“确认生成”。
- 如果用户同时说“确认生成/开始生成/就按这个生成”，直接生成最终原型。
- 缺关键项时只追问缺失项；不关键的信息写“由 AI 合理补全”。

确认单应至少包含：主题、目标、对象、场景类型、页面范围、核心流程、复杂度、视觉风格、色调、布局策略、体验重点、业务数据、参考材料、交互要求、输出形式、验收标准。

## 最终原型要求

生成单文件 HTML，默认保存到当前工作区。使用 HTML、CSS、原生 JavaScript，可直接浏览器打开。

必须做到：

- 第一屏就是可用产品界面，不做营销说明页。
- 按场景生成：B 端重效率、权限、表格、状态和异常；C 端重触控、情绪反馈、内容浏览、转化/探索路径；混合场景兼顾两者。
- 模拟数据真实、字段业务化，包含默认、加载、空状态、错误、成功反馈等状态。
- 适当使用小图标或内联 SVG 做导航、按钮、状态、卡片、指标点缀，让界面更有识别度，但不能喧宾夺主。
- 涉及指标、趋势、对比、分布、看板或图表时，优先用 ECharts CDN 做可交互图表；必须提供无网络或加载失败时的简洁降级。
- 核心按钮、搜索、筛选、切换、弹窗/详情、提交或参数调节等交互可点击演示。
- 桌面和移动端不重叠、不横向溢出；文字不挤出按钮和卡片。
- 生成后尽量用浏览器或本地预览检查；发现明显问题先修再交付。

## 交付

最终回复只说：

- HTML 文件路径。
- 覆盖的页面/流程。
- 已验证或未能验证的事项。

详细设计规则只有在需要调优技能本身时再看 `references/design-rules.md`。
