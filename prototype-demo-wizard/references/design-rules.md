# prototype-demo-wizard 设计规则

仅在优化技能、排查生成质量或需要明确设计细则时读取。日常生成配置器优先用 `scripts/generate_configurator.py`。

## 配置器体验

- 配置器本身要像产品工具，不像静态表单。
- 第一屏直接可配置，不做营销 hero。
- 桌面端左右两栏，右侧 sticky 实时确认单；移动端单列。
- 步骤建议为：需求目标、场景用户、风格体验、参考约束。
- 单选用卡片，多选用 checkbox chips，文本输入只保留必要字段。
- 默认推荐项必须已选中，用户可不填长文本直接复制确认单。
- 支持恢复推荐、应用推荐方向、一键复制、复制反馈、键盘可操作。

## 场景策略

- B 端 SaaS：信息层级、表格筛选、状态流转、权限边界、异常处理、批量效率。
- B 端工作台：待办聚合、任务流、协作审批、处理记录、下一步动作。
- 数据看板：指标总览、趋势洞察、异常定位、钻取分析、结论明确。
- AI 工作台：输入任务、生成过程、引用依据、结果编辑、人工确认。
- C 端 App/小程序：移动触控、路径短、反馈强、底部导航、轻量任务。
- C 端内容/社区：内容浏览、推荐流、互动反馈、收藏关注、继续探索。
- 官网/活动页：首屏吸引、利益点、转化路径、报名/预约/领取状态。

## 色调策略

- 蓝色系：可信、效率、科技、企业服务、学习工具。
- 绿色系：健康、成长、稳定、打卡、效率提升。
- 红色系：活动、提醒、消费、热度、强转化。
- 橙色/暖色系：亲和、生活方式、教育、内容、消费决策。
- 黑白灰高级感：品牌、作品集、设计工具、专业服务。
- 自定义品牌色：用户提供品牌色、品牌名、截图或参考系统。

## 图标使用规则

- 图标只用于增强识别：导航、按钮、状态、空状态、功能卡、指标卡、主题卡。
- 优先用内联 SVG、emoji-free 小图标或 CDN 图标库；常见操作用“图标 + 短文案”，避免只放抽象图标。
- 尺寸以 16-24px 为主，颜色跟随主题色或状态色，不要把图标堆成装饰背景。
- C 端可更活泼，B 端保持克制；所有图标都要服务流程和信息层级。

## ECharts 图表规则

- 涉及趋势、对比、分布、占比、漏斗、指标诊断、监控看板时，优先使用 ECharts。
- 单文件 HTML 可通过 CDN 引入 ECharts；如果无网络或 CDN 失败，必须显示原生 HTML/CSS/SVG/Canvas 降级，不留空白。
- 图表至少包含 tooltip、legend、hover/click 反馈中的两项；看板类优先加筛选、维度切换、dataZoom 或 drilldown 演示。
- 图表容器要有固定高度和响应式宽度，监听 resize；移动端不能横向溢出。
- 图表旁边必须有一句可评审结论或异常解释，不能只有图。

## 质量验收

- 第一屏必须是实际产品界面。
- 核心流程能点击走通。
- 关键状态包含默认、加载、空状态、错误/异常、成功反馈。
- 桌面和移动端无横向溢出、无文字重叠、无按钮挤压。
- 不要卡片套卡片，不要大面积单一紫蓝渐变，不要后台场景套给 C 端需求。
